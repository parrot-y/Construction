# Research Report 05: Construction UX, Role Dashboards & Field Capture

**Access Date:** 2026-10-27  
**Scope:** Role-based dashboard patterns for Kenyan construction, low-bandwidth mobile site-capture flows for field conditions, and jargon-free financial and progress communication for property owners/clients.

## 1. Role-Based Dashboard Architecture

In construction SaaS, generic dashboards fail because different stakeholders on the build have distinct, sometimes opposing information needs. The application presents four tailored dashboard views corresponding to the four V1 roles [Tag: `INTERNAL DECISION — PRD & ARCHITECTURE PLAN`]:

```
                                  [ Authentication ]
                                          │
                   ┌──────────────────────┴──────────────────────┐
                   ▼                                             ▼
        [ Company-Level Scope ]                       [ Project-Level Scope ]
                   │                                             │
         ┌─────────┴─────────┐                         ┌─────────┴─────────┐
         ▼                   ▼                         ▼                   ▼
    ┌──────────┐       ┌──────────┐              ┌───────────┐       ┌──────────┐
    │ Company  │       │ PM / QS  │              │   Site    │       │ Client / │
    │  Admin   │       │Dashboard │              │Supervisor │       │Developer │
    └──────────┘       └──────────┘              └───────────┘       └──────────┘
```

### 1.1 Company Admin / Contractor Dashboard
- **Mental Model:** Portfolio health, cash flow, and executive risk management.
- **Key Metrics Displayed:**
  - Active projects count & total portfolio contract value (KES).
  - Portfolio budget vs. actual expenditure to date.
  - Critical pending actions: Items requiring executive approval (variations over KES limit, high-value purchase orders).
  - Cash flow runway: Receivables (unpaid IPCs submitted to clients) vs. payables (approved supplier/subcontractor costs).

### 1.2 Project Manager / Quantity Surveyor (PM / QS) Dashboard
- **Mental Model:** Project commercial control, BOQ tracking, and contract administration.
- **Key Metrics Displayed:**
  - Active project status, project start date, scheduled completion, days elapsed vs. remaining.
  - BOQ section-by-section budget consumption table (`Current Budget`, `Actual Spend`, `Variance`).
  - Pending contractor payment claims and draft Interim Valuations.
  - Variation register: Submitted vs. approved vs. rejected change orders.
  - Alignment indicator: Physical progress % vs. cost consumption %.

### 1.3 Site Supervisor / Foreman Mobile View
- **Mental Model:** Daily task execution, site safety, and field proof logging.
- **Key Metrics Displayed:**
  - **"Today's Site Diary" status card:** Weather condition selector (Sunny, Rain, Muddy), site status (Operational, Rained Out, Stalled).
  - **Labor Headcount widget:** Quick counters for skilled vs. casual laborers on site today.
  - **Quick Action Bar:** Tap targets for: "Add Site Photo", "Log Material Delivery", "Record Progress Update".
  - **Pending Requests:** Status of requested materials (Approved, In Transit, Delivered).

### 1.4 Client / Developer Portal
- **Mental Model:** Peace of mind, transparency, and simple financial oversight.
- **Key Metrics Displayed:**
  - Overall project physical completion percentage (visual progress bar).
  - Financial summary: Original Contract Budget, Approved Changes, Total Spent, Remaining Balance.
  - Recent visual evidence: Carousel of timestamped site photos.
  - Action Required: Single-click review of pending variation requests submitted for client approval.

## 2. Low-Bandwidth Mobile Site-Capture Flows

### 2.1 Environmental Constraints on Kenyan Building Sites
Site supervisors and foremen operate under severe real-world constraints [Tag: `UNVERIFIED — GENERAL FIELD PRACTICE`]:
- **High Glare & Sunlight:** Bright outdoor environments wash out low-contrast UI screens.
- **Physical Barriers:** Hands may be dusty, wet, or gloved; fine motor precision is degraded.
- **Spotty 3G/Edge Connectivity:** Peripheral construction sites (e.g. Athi River, Ruiru, Kitengela, upcountry) experience frequent connection drops and latency >2,000ms.
- **Data Cost Sensitivity:** Site supervisors often run on personal prepaid mobile data bundles.

### 2.2 UX Principles for Field Site Capture
1. **Zero-Wait Interaction (Optimistic UI):**
   - Tapping "Save Progress" or "Upload Photo" must instantly update the screen and dismiss the form.
   - No blocking loading spinners waiting for remote HTTP requests.
   - A persistent, subtle sync pill appears: *"Saved on device • 2 updates waiting to sync"*.
2. **Client-Side Image Compression:**
   - Modern smartphone cameras capture high-resolution photos (5MB–15MB per photo). Uploading uncompressed photos fails on 3G and quickly depletes data bundles.
   - Use browser Canvas API (or `browser-image-compression`) to resize photos to **max 1280px width, JPEG quality 0.7**, before storing in IndexedDB or uploading.
   - Compresses photo payload significantly with zero loss of structural readability.
   - Preserve or extract image metadata: local device timestamp and GPS coordinates (if permitted).
3. **Ergonomic Touch Targets:**
   - Minimum tap target size of **48×48 CSS pixels** for all buttons, inputs, and toggles (aligned with W3C WCAG 2.1 / 2.2 Target Size standards) [Tag: `VERIFIED` - [W3C WCAG 2.1 Success Criterion 2.5.5](https://www.w3.org/WAI/WCAG21/Understanding/target-size.html)].
   - Bottom navigation bar: Primary action buttons positioned within natural thumb reach.
   - Number steppers (`+` and `-` buttons) for labor headcounts instead of requiring keyboard popup.

## 3. Explaining Budget vs. Progress to Clients Without Jargon

### 3.1 The Problem with Earned Value Management (EVM) for Clients
Traditional construction project management relies on Earned Value Management terms:
- *Cost Performance Index (CPI)*
- *Schedule Performance Index (SPI)*
- *Actual Cost of Work Performed (ACWP)*
- *Budgeted Cost of Work Scheduled (BCWS)*

To a private developer or homeowner investing into a commercial or residential build, these terms are alienating and obscure real project health.

### 3.2 The Plain-Language Financial Card Pattern
The client portal presents five transparent, plain-language numbers [Tag: `INTERNAL DECISION — GEMINI.MD SECTION 8`]:

```
┌────────────────────────────────────────────────────────┐
│  PROJECT FINANCIAL OVERVIEW                            │
│                                                        │
│  Original Agreed Budget:          KES 12,000,000.00    │
│  Approved Changes (Variations):   + KES  850,000.00    │
│  ───────────────────────────────────────────────────   │
│  Current Approved Budget:         KES 12,850,000.00    │
│                                                        │
│  Total Spent to Date:             KES  6,425,000.00    │
│  Budget Used:                     50.0%                │
│                                                        │
│  Physical Work Completed:         48.0%                │
│                                                        │
│  ● Status: On Track                                    │
└────────────────────────────────────────────────────────┘
```

### 3.3 Rule for Variance Warnings
When budget consumption is materially ahead of recorded physical progress (e.g. 70% budget spent vs. 40% physical work done), the UI displays a neutral, factual flag:

> **Project Health Notice:**  
> "Cost consumption is significantly ahead of recorded physical progress. Review project costs and progress records."

- **Strict Tone Rule:** Never use words such as *"fraud"*, *"theft"*, *"stolen"*, or *"overbilled"*. The software reports verified arithmetic facts and prompts professional review, maintaining legal neutrality and collaborative trust between contractor and client [Tag: `INTERNAL DECISION — GEMINI.MD WORKING AGREEMENT`].
